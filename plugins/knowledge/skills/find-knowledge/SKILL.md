# Find recorded knowledge

Read the starting storage's instructions and source map. Begin with stores the
user named, or the current storage when none were named. Follow documented
relationships to relevant canonical sources; do not invent routes or search
unrelated stores merely because they are available.

## Search

Keep the user's wording, then try a small set of useful variants: aliases,
scripts or transliterations, inflections, and a cautious category paraphrase.
Prefer exact or keyword search before hybrid or semantic search. A semantic
near-hit is only a lead: verify it against the source text before reporting it.

Use each source's native read or search interface and current tool schema.
Follow only documented routes within the user's requested scope and existing
authorization. Narrow chats or other large collections by mapped topic metadata
when useful, and search each authorized source separately when no global search
exists. Account for pagination, truncation, excluded paths, and inaccessible
attachments; absence from partial results is not absence from the source.

Stop when the requested depth is covered or a supported answer makes further
search immaterial. Do not broaden into web research unless the user asks for it
or a mapped canonical source requires opening a direct link. Do not write,
capture, reorganize, or repair anything during a retrieval request.

## Report

Lead with the answer. For each useful finding, give a stable source locator such
as a note path and section or a chat, topic, message identifier, and date.
Separate source statements from inference.

Summarize coverage when it affects confidence: sources searched, unavailable,
partially covered, or deliberately not searched. If nothing relevant was found,
say “no match in the searched sources”; say that the knowledge does not exist
only when the relevant mapped sources were exhaustively covered.
